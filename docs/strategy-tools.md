# Original strategy tools and their boundaries

Programmed Minds keeps one automated sequence: research → critique → improvement → critique → plan → critique → design → coding handoff → real checks → audit. For a named competition it now requires a source-linked strategy assessment with an explicit `go`, `clarify`, or `stop` decision before creating the coding handoff. A `go` is permission to investigate/build, never a forecast or guarantee of winning. The assessment records the strongest plausible rival, a losing scenario, and a test that could overturn its thesis.

| Original project | Useful original operation | Where it belongs | Boundary |
| --- | --- | --- | --- |
| [BMad Method](https://github.com/bmad-code-org/BMAD-METHOD) | `bmad-deep-recon`, `bmad-forge-idea`, optionally `bmad-prfaq` | Explore a candidate or customer case before submitting a brief | Conversational research and challenge; no copied skills, no automatic claims of novelty or market proof |
| [gstack](https://github.com/garrytan/gstack) | `/office-hours`, `/plan-ceo-review`, `/plan-eng-review`, later `/qa` | Optional independent challenge of the selected idea, plan or a running target | Not an extra automatic approval gate; its Codex outside-review command uses Claude Code and may require a paid/authenticated CLI |
| [GitHub Spec Kit](https://github.com/github/spec-kit) | Optional `assess` extension, then specification for a target project | A separate documented decision when the brief is still uncertain | Do not run its full plan/build sequence on top of this project's own plan and Superpowers |
| [obra/superpowers](https://github.com/obra/superpowers) | Coding plan, tests, review and verification | Execute the generated `HANDOFF.md` in the trusted target repository | This project emits the handoff and cannot assert that external implementation occurred |

The names above identify original projects, not bundled or executed dependencies. To use them in Codex, install the *original* projects in your coding environment according to their current upstream instructions. BMad documents `codex plugin marketplace add bmad-code-org/bmad-plugins`; gstack documents `./setup --host codex`; Spec Kit documents `uv tool install specify-cli` followed by `specify extension add assess` in its own configured project. Their setup may add global skills, agent instructions and commands, so select the workflows you need and read the resulting instructions before use. Programmed Minds does not install them into a user's Codex account or run their commands through model output.

For a hackathon, put the official rules URL, judging criteria and deadline in `examples/brief.json`. If you have an external BMad, gstack or Spec Kit report, summarize the claims under `external_assessments` in the brief and attach original URLs where possible. The researcher verifies those claims independently; the system does not treat a pasted report or a reviewer's confidence as evidence. If `competition.rules_url` is set, research must include that exact observed URL. An unknown rule, unsupported edge over rivals, or untestable advantage should produce `clarify` or `stop`; those decisions block the handoff until the brief or evidence changes in a fresh run.

The producer/critic roles retain their separate provider identities. A strategic verdict is generated by a model and checked for required fields and source IDs, so it remains a decision aid. The judge's rubric, actual competitors and winning outcome may still be unknown. Objective product and security checks remain the original CLIs listed in `docs/tools.md` and the post-implementation audit.
